## 已处理的问题

| 问题 | 处理与验证 |
| --- | --- |
| Fast Track / HK 新题修改 `fast-track.js`，但 PR 文件白名单不允许该文件 | 抽出 `scripts/check-submission-diff.cjs`，统一六个允许的数据文件；四个校区/类型组合的真实导入结果均通过白名单，代码及路径穿越被拒绝。 |
| v2 的 `term`、`linkedQuestionId` 会被正则隐式转换，数组可能通过校验 | Worker 与导入器均先校验字符串类型；新增反例测试，非法输入不进入验证服务、不修改题库。 |
| Turnstile 返回空值时可能抛出未处理异常，非布尔成功值也可能被接受 | 仅接受 `success === true` 且域名、action 正确的结果，空响应和错误类型返回受控拒绝。 |
| 星数缓存未排除未来时间戳 | 增加有限数值及时间范围检查；覆盖官方接口、备用源、零值、缓存、双源失败。 |
| 练习页与投稿页混合大量内联逻辑、样式 | 原样提取四个页面脚本到 `js/`、两份专用样式到 `css/`，保留经典脚本与加载顺序；CSS 仅更正图片相对路径。 |
| CI 内嵌检查长、本地没有统一入口 | `npm run check` 校验页面、资源、文档链接、稳定数据及语法；`npm test` 执行 Node 测试。CI 复用相同入口。 |
| 浏览器测试依赖 Linux 系统 Chrome，且随机抽题可能令笔记断言点击隐藏卡片 | 使用锁定的 Playwright Chromium，支持 Windows / Linux；笔记测试明确回到固定题目所在页，计时断言兼容双语并校验运行状态。 |
| 测试依赖公共星数、人机验证和投稿网络 | 浏览器回归隔离第三方请求并阻止真实投稿；服务端请求边界单独由 Worker 测试验证。 |
| README 和审核文档仍含旧 v1 / D-only 流程及不明确的线上状态 | 重整 README，补齐文件分工、检查命令及维护约束；同步 v2、小问/问法补充规则、完整白名单；历史部署快照明确标为历史。 |
| 生成物和本地密钥没有统一忽略规则 | 增加 `.gitignore`、文本换行约定及锁文件，浏览器产物和本地密钥不纳入版本控制。 |

- 审查前 69 项测试通过；整理后 **75 项 Node 测试通过**。
- 结构校验通过：五页内部路径与锚点、共享导航与页脚、资源路径、文档本地链接、63 个含旧版兼容项的稳定题目 ID、场次及经验关联。63 不是页面显示的去重练习题总数。

## 后续维护

1. 页面改动运行 `npm run check`、`npm test`；涉及交互、排版或资源加载顺序时，再运行 `npm run test:browser`。
2. 保持静态导航和页脚五页同步，专用样式位于共享样式之后；页面脚本继续位于相应数据脚本之后。
3. 已发布题目的小问顺序与笔记键相关，不进行无迁移的重排；新场次、问法和小问优先写入关联记录。
4. 修改投稿字段时同时检查前端、Worker、导入器、规范及反例测试。修改 PR 白名单只编辑共享校验脚本，并验证全部校区/类型。
5. Worker 需要独立部署。自动化测试不证明生产 Turnstile、线上 Worker、原生文件夹选择器或远程部署已经通过验证。
